# Ivanka Accounts — лабораторний проєкт 6

Піварчук Іванна. JavaScript, Node.js 24+, Express 5, SQLite, scrypt, email OTP, OpenID Connect.

## Запуск без Docker

```bash
npm ci
node configure.js
npm run provider
```

Залиште провайдер працювати. В іншому терміналі в тій самій папці:

```bash
npm start
```

Відкрийте http://localhost:3000. `configure.js` створить випадковий SESSION_SECRET і випадковий пароль початкового адміністратора; пароль виводиться один раз. Не публікуйте `.env`. Якщо файл уже існує, генератор відмовиться його перезаписувати.

Windows Git Bash: ті самі команди. SQLite вбудована у Node.js; окремий сервер БД не потрібний.

## Функції

1. Реєстрація; серверна політика пароля: 8–128 символів, великі/малі літери, цифра, спецсимвол. Індикатор вимог та перемикач видимості пароля.
2. Навчальна арифметична CAPTCHA з двохвилинним строком дії, одноразовим використанням і лімітом запитів. Це базова демонстрація механізму; арифметика не забезпечує стійкості сучасного антибот-сервісу.
3. Активація через одноразове випадкове посилання зі строком 15 хвилин. У БД зберігається SHA-256 токена, а не відкритий токен.
4. Три невдалі входи блокують акаунт на 60 секунд. Ліміти також застосовано до IP. Адміністратор бачить час UTC, IP, email, результат; може блокувати/розблоковувати й скидати ліміт. Блокування відкликає попередні сеанси.
5. Email OTP як 2FA: 6 цифр, 5 хвилин, не більше 5 спроб. Увімкнення після підтвердження поточного пароля; вимкнення додатково вимагає OTP. Для OIDC-акаунта без локального пароля зміна 2FA підтверджується OTP.
6. OIDC Authorization Code Flow + PKCE S256, state, nonce, JWKS-перевірка підпису ID Token, issuer, audience, строку та email_verified. Акаунти зв'язуються за issuer+sub; небезпечного автоматичного злиття за email немає.
7. Відновлення пароля через одноразовий токен 15 хвилин. Зміна відкликає старі сеанси; 2FA зберігається.

Паролі зберігаються як scrypt + індивідуальна випадкова сіль (16 байтів). Порівняння похідних ключів — timingSafeEqual. Cookie HttpOnly, SameSite=Lax; CSRF-токени, Helmet, параметризовані SQL-запити, перевірка ролей на сервері. Користувач читає лише власний профіль; адміністративні API відхиляють роль user.

## Пошта та OIDC у демонстрації

`MAIL_MODE=preview` — локальна тестова пошта в меню застосунку. Листи не надсилаються зовнішнім адресатам. Скринька спеціально доступна без входу лише на локальному стенді. У production цей режим заборонено.

`provider.js` запускає **окремий локальний тестовий** провайдер з пакета `oidc-provider`. Це справжній протокол OIDC із підписаним ID Token, але це **не демонстрація Google/Microsoft**. Стандартний development UI провайдера дозволяє ввести тестовий account ID без пароля. Провайдер в пам'яті та його тестові ключі непридатні для production.

Для зовнішнього OIDC-провайдера зареєструйте клієнт, redirect URI `APP_URL/auth/callback`, scope `openid email profile`; задайте OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET. Підтримується передавання client secret у тілі token-запиту (`client_secret_post`) або public client + PKCE. Провайдер повинен повертати email_verified=true та ID Token RS256/ES256. Google/Microsoft потребують окремих налаштувань у їх консолі та не перевірялися в цьому середовищі.

Для реальних листів задайте MAIL_MODE=smtp та SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, MAIL_FROM. Для production: HTTPS, NODE_ENV=production, Secure cookie; постійний OIDC-провайдер, надійні SMTP/антибот-сервіси та спільний ліміт запитів для кількох процесів. Не вмикайте preview пошту у відкритій мережі. Поточний ліміт IP зберігається в пам'яті одного процесу; блокування акаунтів і сесії — в SQLite.

## Тести

```bash
npm test
npm audit --omit=dev
```

Інтеграційний тест запускає окремий HTTP-сервер та тимчасову БД, перевіряє політику пароля, різні солі, активацію й повтор токена, ліміт входів, адміністрування, RBAC, OTP і повтор коду, відновлення пароля, відкликання сеансів і CSRF. OIDC та SMTP зовнішніх сервісів потребують окремої інтеграційної перевірки після конфігурації.

## Структура

- server.js — маршрути, сеанси, RBAC, OIDC, активація та відновлення.
- src/security.js — хешування, перевірка політики, випадкові токени/OTP.
- src/database.js — схема SQLite та сховище сеансів.
- src/mail.js — SMTP або тестова скринька.
- public/ — вебінтерфейс.
- test/ — автоматичні перевірки.
- docs/video-scenario.md — сценарій запису за таблицею завдання.

## Публікація

У Git виключено `.env`, базу, журнали, node_modules і записи. `test/` містить лише вигадані тимчасові тестові облікові дані, які не використовуються сервером. Не додавайте реальні поштові адреси, SMTP-паролі, client secrets, cookie або експорт листів.
